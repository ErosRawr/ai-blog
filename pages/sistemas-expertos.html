Sistemas Expertos

📖 Lectura: 14 min 🏷️ Unidad IV 📝 Tema 4.6

4.6.1 Conceptos Básicos

Un sistema experto (SE) es un programa de IA que emula el conocimiento y razonamiento de un experto humano en un dominio específico. Fue la primera aplicación comercial exitosa de la IA, popularizada en los años 80.

🏗️ Arquitectura de un sistema experto

Base de conocimientos: Reglas de producción y hechos del dominio (el «saber» del experto).
Motor de inferencia: Algoritmo que aplica las reglas (forward/backward chaining).
Memoria de trabajo: Hechos del caso actual que se está resolviendo.
Módulo de explicación: Justifica sus conclusiones al usuario («¿por qué llegaste a esa conclusión?»).
Interfaz de usuario: Permite al usuario ingresar datos y ver resultados.
Módulo de adquisición: Herramientas para que el ingeniero del conocimiento añada reglas.

👨‍⚕️

Experto humano

Persona con años de experiencia en el dominio. Su conocimiento se extrae y codifica en reglas.

🔧

Ingeniero del conocimiento

Especialista que entrevista al experto y traduce su saber en reglas formales para el sistema.

👤

Usuario final

Persona no experta que consulta al sistema para obtener diagnósticos, recomendaciones o soluciones.

4.6.3 Desarrollos Actuales y Aplicaciones

Clásico

MYCIN (1976) — el pionero

Sistema de diagnóstico de infecciones bacterianas de Stanford. 600 reglas, precisión comparable a especialistas. Introdujo factores de certeza.

Industria

Motores de reglas de negocio

Drools (Java), CLIPS (C), Jess (Java): sistemas de producción usados en banca, seguros, telecomunicaciones para automatizar decisiones.

Moderno

SE + Machine Learning

Sistemas híbridos: reglas para lógica de negocio + ML para predicción. Explicable AI (XAI) retoma la filosofía de los SE.

Actual

LLMs como «expertos» generales

ChatGPT y similares actúan como SE generalistas, pero carecen de garantías formales. Los SE clásicos siguen siendo preferidos en dominios críticos (medicina, aviación).

🛠️ Herramientas clave

CLIPS: Entorno clásico para construir SE basados en reglas (open source).
Drools: Motor de reglas empresarial en Java (Red Hat).
Pyknow / Experta: Framework Python para SE (inspirado en CLIPS).
Protégé: Editor de ontologías para bases de conocimiento complejas.

⚠️ SE vs. LLMs: ¿cuándo usar cada uno?

Usa SE cuando: necesitas explicabilidad total, el dominio es bien definido, hay regulación estricta (medicina, finanzas), las reglas no cambian frecuentemente.
Usa LLMs cuando: el dominio es abierto, se necesita flexibilidad con lenguaje natural, los datos son masivos y cambiantes, la precisión «perfeccionable» es aceptable.

🎯 Actividad Práctica

💡 Ejercicio: Construye un mini sistema experto con Python

A continuación desarrollaremos un prototipo funcional para un sistema de diagnóstico de problemas de red utilizando la librería experta (una evolución de Pyknow inspirada en CLIPS).

from experta import *

class ProblemaRed(Fact):
    """Estructura de hechos para la memoria de trabajo."""
    pass

class DiagnosticoRed(KnowledgeEngine):
    # Regla 1: Falla de energía
    @Rule(ProblemaRed(sintoma='sin_conexion'), ProblemaRed(luces_router='apagadas'))
    def falla_energia(self):
        print("Diagnóstico: El router no tiene energía. Solución: Revisa la conexión eléctrica o el adaptador.")

    # Regla 2: Caída del ISP
    @Rule(ProblemaRed(sintoma='internet_lento_o_nulo'), ProblemaRed(luces_router='parpadean_rojo'))
    def falla_isp(self):
        print("Diagnóstico: Falla en el servicio de tu proveedor. Solución: Contacta a soporte técnico (ISP).")

    # Regla 3: Falla de Servidor DNS
    @Rule(ProblemaRed(sintoma='sin_conexion'), ProblemaRed(luces_router='encendidas_verde'))
    def falla_dns(self):
        print("Diagnóstico: Posible fallo de DNS. Solución: Intenta cambiar los DNS de tu dispositivo (ej. 8.8.8.8).")

# Instanciación y ejecución del motor de inferencia
motor = DiagnosticoRed()
motor.reset() # Prepara la memoria de trabajo vacía

# Insertamos hechos en la memoria de trabajo del sistema
motor.declare(ProblemaRed(sintoma='sin_conexion', luces_router='encendidas_verde'))

# Disparamos el motor para evaluar reglas e inferir la respuesta
print("--- Iniciando Análisis del Sistema Experto ---")
motor.run()

Análisis: Copia este código, instálalo con pip install experta y experimenta cambiando los hechos. ¿Qué sucede si ingresas un hecho para el cual el sistema no tiene una regla codificada?

📝 Evaluación — Tema 4.6

Pregunta 1 de 5
¿Cuál es el componente responsable de aplicar las reglas sobre los hechos actuales para generar una nueva conclusión?
A La Memoria de Trabajo
B La Base de Conocimientos
C La Interfaz de Usuario
D El Motor de Inferencia
✅ Correcto. El motor de inferencia actúa como el "cerebro" lógico, usando encadenamiento hacia adelante (forward chaining) o hacia atrás (backward chaining) para emparejar reglas y disparar resultados.
Pregunta 2 de 5
¿Qué función vital cumple el "Ingeniero del Conocimiento" en el desarrollo de un Sistema Experto?
A Es la persona que consulta al sistema una vez terminado para resolver sus problemas del día a día.
B Es el especialista en software que entrevista al experto humano y traduce o programa su experiencia empírica en reglas formales para la máquina.
C Es un ente de Inteligencia Artificial que extrae la información directamente de la web sin ayuda humana.
D Se encarga exclusivamente de diseñar la interfaz visual (UI/UX) del sistema.
✅ Correcto. Es el puente entre el profesional experto (como un médico experimentado) y el código de la base de conocimientos.
Pregunta 3 de 5
¿Cuál es la diferencia primordial entre un Sistema Experto de "Diagnóstico" y uno de "Configuración"?
A El de diagnóstico busca identificar la causa de un problema a través de síntomas (ej. MYCIN); el de configuración busca diseñar de forma óptima un sistema complejo (ej. ensamblar una computadora).
B El de configuración es analógico, mientras que el de diagnóstico requiere hardware especializado cuántico.
C Son sinónimos; ambos realizan exactamente la misma tarea en industrias diferentes.
D El diagnóstico se usa en robótica industrial, y la configuración solo en medicina preventiva.
✅ Correcto. Tienen objetivos finales distintos: encontrar el error (diagnóstico) versus crear un plan de ensamblaje (configuración).
Pregunta 4 de 5
A diferencia de los Modelos de Lenguaje Grandes (LLMs), una gran ventaja del Módulo de Explicación de los SE es:
A Que hablan en múltiples idiomas nativamente.
B Que pueden conectarse y navegar por internet en tiempo real para encontrar la respuesta.
C Su total explicabilidad y transparencia. Permiten justificar la conclusión alcanzada mostrando el camino exacto de las reglas que se activaron (sin "cajas negras").
D Su capacidad para aprender de manera autónoma sin que se le ingresen reglas nuevas.
✅ Correcto. Esta trazabilidad estricta los hace indispensables en sectores como la salud, la banca o la aviación comercial.
Pregunta 5 de 5
Históricamente, ¿por qué es tan famoso el proyecto MYCIN (desarrollado en Stanford en 1976)?
A Fue el primer programa en derrotar a un humano en el ajedrez.
B Fue el creador del algoritmo de Redes Neuronales convolucionales.
C Fue pionero como sistema experto capaz de diagnosticar infecciones bacterianas de la sangre introduciendo el uso de "factores de certeza", compitiendo con la precisión humana.
D Logró traducir 20 idiomas diferentes en tiempo real durante la guerra fría.
✅ Correcto. MYCIN fue fundamental para demostrarle a la industria que la Inteligencia Artificial podía resolver problemas del mundo real y tener utilidad médica.

Conclusión

Los sistemas expertos son la aplicación clásica más exitosa de la IA simbólica. Aunque la era de los LLMs ha cambiado el panorama, los SE siguen siendo insustituibles en dominios donde la explicabilidad, trazabilidad y garantía formal son obligatorias. CLIPS, Drools y Experta permiten construir SE funcionales hoy. El futuro está en la combinación: reglas formales para lógica de negocio + ML para predicción + LLMs para interfaz natural.
