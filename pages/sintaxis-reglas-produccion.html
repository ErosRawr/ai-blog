Sintaxis de las Reglas de Producción

📖 Lectura: 10 min 🏷️ Unidad III 📝 Tema 3.4

Formato sintáctico general

La sintaxis define la forma correcta de escribir una regla de producción. Es el «idioma formal» que el motor de inferencia puede leer y ejecutar. Toda regla sigue una estructura precisa:

// Estructura general de una regla de producción
REGLA <nombre_único>
  PRIORIDAD: <número>           // opcional
  SI
    <patrón₁> Y
    <patrón₂> Y
    NO <patrón₃>
  ENTONCES
    <acción₁>
    <acción₂>

Elementos sintácticos

ElementoDescripciónEjemplo
ConstanteValor fijo literaltemperatura = 38, color = rojo
VariablePlaceholder que unifica con cualquier valor?x, ?nombre, ?temp
PatrónPlantilla que se compara con hechos(sintoma (tipo ?x) (valor alto))
Operadores lógicosAND, OR, NOT entre condicionesSI cond1 Y cond2 Y NO cond3
RestriccionesCondiciones sobre variables?temp > 37.5, ?edad < 18
AccionesAssert, retract, modify, print(assert (diagnostico gripe))

Sintaxis en CLIPS (ejemplo real)

; Definición de template (estructura de hechos)
(deftemplate paciente
   (slot nombre)
   (slot edad (type INTEGER))
   (slot temperatura (type FLOAT)))

; Regla con variables y restricciones
(defrule fiebre-alta
   (paciente
      (nombre ?nom)
      (temperatura ?t&:(> ?t 38.5)))
   =>
   (assert (alerta (paciente ?nom) (tipo fiebre-alta)))
   (printout t "ALERTA: " ?nom " tiene fiebre alta: " ?t "°C" crlf))

; Regla con negación
(defrule sin-alergias
   (paciente (nombre ?nom))
   (not (alergia (paciente ?nom)))
   =>
   (printout t ?nom " no tiene alergias registradas" crlf))

🎯 Actividad práctica

💡 Ejercicio: Escribe reglas con sintaxis formal

Dominio: Sistema de aprobación de créditos bancarios.

1. Define templates/hechos: cliente(nombre, edad, ingreso_mensual, historial_crediticio, deuda_actual).

2. Escribe al menos 5 reglas usando la sintaxis formal con variables y restricciones:

• R1: Si ingreso > 15,000 Y historial = bueno → crédito_aprobado

• R2: Si edad < 18 → rechazado_por_menor_de_edad

• R3: Si deuda_actual > 50% del ingreso → rechazado_por_deuda

3. Usa la sintaxis de CLIPS o pseudocódigo formal visto en clase.

4. Muestra la traza de ejecución para un cliente ejemplo.

📝 Evaluación — Tema 3.4

Pregunta 1 de 5
¿Cuál es la diferencia fundamental entre una constante y una variable en el antecedente de una regla?
A La constante cambia de valor durante la ejecución, la variable es estática.
B La constante exige una coincidencia literal exacta, mientras que la variable actúa como un comodín que unifica con cualquier valor.
C Las variables solo pueden usarse en el consecuente (RHS).
D No hay diferencia en motores modernos como CLIPS.
✅ Correcto. Las variables hacen que las reglas sean reutilizables para múltiples hechos distintos.
Pregunta 2 de 5
¿Qué representa exactamente un «patrón» dentro de la memoria de trabajo?
A Un bucle condicional FOR.
B Una plantilla estructural que se utiliza para buscar hechos coincidentes.
C El mecanismo que detiene la ejecución del motor.
D Una función matemática que calcula prioridades.
✅ Correcto. El patrón es la condición específica que un hecho debe satisfacer para que la regla se active.
Pregunta 3 de 5
¿Cómo se traduciría correctamente a pseudocódigo formal la regla: "Si un estudiante tiene promedio >= 9.0 y asistencia >= 90%, entonces beca aprobada"?
A SI (estudiante (promedio ?p>=9.0) (asistencia ?a>=90)) ENTONCES (assert (beca aprobada))
B SI beca aprobada ENTONCES promedio >= 9.0 Y asistencia >= 90
C (assert estudiante) => (promedio 9.0)
D SI estudiante ENTONCES promedio = 9.0 OR asistencia = 90
✅ Correcto. Se declaran las restricciones lógicas en el antecedente y se añade el nuevo hecho en el consecuente.
Pregunta 4 de 5
¿Cuál es el efecto de la instrucción «retract» cuando se ejecuta en el consecuente de una regla?
A Retrocede la ejecución al inicio del programa.
B Imprime un valor en la terminal.
C Elimina permanentemente un hecho específico de la memoria de trabajo.
D Modifica la prioridad (salience) de la regla en tiempo real.
✅ Correcto. Se utiliza para borrar hechos que ya no son válidos, manteniendo la memoria de trabajo actualizada.
Pregunta 5 de 5
¿Por qué es una buena práctica utilizar construcciones como `deftemplate` en lugar de agregar hechos simples aislados?
A Permiten definir estructuras complejas con atributos nombrados (slots) y tipos de datos fuertes.
B Aumentan la velocidad del motor de inferencia en un 500%.
C Son la única manera de imprimir resultados en CLIPS.
D Evitan que el usuario tenga que escribir la sección ENTONCES de la regla.
✅ Correcto. Aportan una sintaxis estructurada, similar a las clases u objetos, garantizando orden y evitando errores de tipado.

Conclusión

Dominar la sintaxis de las reglas de producción es esencial para implementar sistemas expertos funcionales. La sintaxis formal garantiza que las reglas sean precisas, no ambiguas y ejecutables por un motor de inferencia. Las variables, restricciones y patrones son las herramientas que convierten el conocimiento experto en código procesable.
