Representación del Conocimiento mediante Reglas

📖 Lectura: 13 min 🏷️ Unidad III 📝 Tema 1 de 5

¿Qué son las reglas en IA?

Las reglas son una de las formas más naturales e intuitivas de representar el conocimiento humano en un sistema de IA. Tienen la forma SI condición ENTONCES acción (IF-THEN), y permiten codificar el saber de un experto de forma que la máquina pueda razonar con él.

Piensa en cómo un médico piensa: «SI el paciente tiene fiebre alta Y tos persistente, ENTONCES sospechar neumonía». Ese razonamiento condicional es exactamente lo que las reglas capturan.

📐 Estructura general de una regla

SI <antecedente> ENTONCES <consecuente>

Antecedente (LHS — Left Hand Side): Lista de condiciones conectadas con operadores lógicos (Y, O, NO). Es la premisa.
Consecuente (RHS — Right Hand Side): Conclusión o acción a ejecutar si el antecedente es verdadero.

Ejemplo: SI (temperatura > 38°C) Y (tos persistente) ENTONCES (sospechar neumonía)

Ventajas y desventajas de las reglas

🗣️

Naturalidad

Se parecen al razonamiento humano. Los expertos pueden entenderlas y validarlas fácilmente sin necesidad de entrenamiento técnico.

🧩

Modularidad

Cada regla es independiente. Puedes agregar, eliminar o modificar reglas sin afectar significativamente las demás.

🔍

Explicabilidad

Se puede explicar exactamente por qué el sistema tomó una decisión mostrando la cadena de reglas usadas (trazabilidad).

⚡

Eficiencia

Motor de inferencia optimizado. Para dominios bien definidos, las reglas pueden ser muy rápidas en ejecución.

⚠️

Fragilidad

Cambios pequeños en el mundo real requieren muchas nuevas reglas. El sistema puede ser frágil ante situaciones no anticipadas.

📊

Escalabilidad limitada

Bases de conocimiento muy grandes (miles de reglas) se vuelven difíciles de mantener y pueden tener conflictos.

🎯

Formalismo

Sintaxis formal y precisa que se puede implementar computacionalmente sin ambigüedad. Compatible con lógica de primer orden.

🔗

Encadenamiento

Se pueden conectar en cadenas (hacia adelante o atrás) para resolver problemas complejos. Las conclusiones se convierten en nuevas premisas.

Ejemplo paso a paso: diagnóstico automotriz

Veamos cómo un sistema de reglas rastrea el razonamiento para diagnosticar problemas de un automóvil. Primero, definimos la base de reglas:

// BASE DE REGLAS — Diagnóstico Automotriz

Regla 1: SI motor_no_arranca Y luces_no_encienden
         ENTONCES batería_descargada (CF: 0.95)

Regla 2: SI motor_no_arranca Y luces_encienden
         ENTONCES motor_de_arranque_dañado (CF: 0.85)

Regla 3: SI motor_no_arranca Y sonido_clic_repetido
         ENTONCES batería_agotada (CF: 0.90)

Regla 4: SI batería_descargada
         ENTONCES acción: recargar_o_reemplazar_batería

Regla 5: SI motor_arranca Y humo_negro
         ENTONCES mezcla_de_combustible_rica (CF: 0.75)

Regla 6: SI motor_arranca Y humo_azul
         ENTONCES quema_aceite (CF: 0.80)

Ahora, el usuario reporta estos síntomas. El motor rastrea cómo el sistema razona:

// HECHOS OBSERVADOS (entrada del usuario)
motor_no_arranca = true
luces_no_encienden = true
sonido_clic_repetido = false

// ═══════════════════════════════════════
// CICLO DE INFERENCIA
// ═══════════════════════════════════════

// PASO 1: Motor compara hechos con antecedentes
//  ✓ Regla 1 coincide: motor_no_arranca=T Y luces_no_encienden=T

// PASO 2: Ejecutar Regla 1
Conclusión: batería_descargada = true (CF: 0.95)

// PASO 3: Nuevo hecho agregado, verificar de nuevo
//  ✓ Regla 4 ahora coincide: batería_descargada=T

// PASO 4: Ejecutar Regla 4
Acción: RECARGAR O REEMPLAZAR BATERÍA

// PASO 5: No hay más reglas que aplicar → FIN
💡 Observa el encadenamiento

La conclusión de Regla 1 (batería_descargada) se convierte en un nuevo hecho que activa Regla 4. Esto es encadenamiento hacia adelante y es el corazón del razonamiento basado en reglas.

El ciclo de inferencia

1. Matching

¿Cuáles reglas aplican?

El motor compara los hechos actuales con los antecedentes de todas las reglas. Las que coinciden van a la agenda de conflictos.

2. Resolución

¿Cuál regla ejecutar?

Si hay múltiples reglas candidatas, se aplica una estrategia (FIFO, por especificidad, por factor de certeza, etc.).

3. Ejecución

Ejecutar la regla ganadora

Se agregan nuevos hechos a la base de datos de trabajo. Las conclusiones se añaden y pueden activar nuevas reglas.

4. Iteración

Repetir hasta convergencia

El ciclo se repite hasta que no hay más reglas que se puedan activar, o se alcanza la meta.

🎯 Actividad práctica

💡 Ejercicio: Diseña un sistema de reglas

Dominio: Soporte técnico de una empresa de software.

Tareas:

1. Define al menos 8 reglas para diagnosticar problemas comunes (conexión internet, impresora, permisos de usuario, software corrupto, etc.).

2. Identifica los hechos iniciales que el sistema necesita recopilar (¿qué preguntas hace al usuario?).

3. Muestra cómo se encadenan al menos 3 reglas para llegar a una solución.

4. ¿Qué pasa si dos reglas pueden activarse simultáneamente? Propón una estrategia de resolución de conflictos.

Bonus: Asigna factores de certeza (CF) a tus reglas basándote en la confiabilidad de cada diagnóstico.

📝 Evaluación — Tema 3.1

Pregunta 1 de 5
¿Cuál es la estructura básica de una regla en IA?
A MIENTRAS condición HACER acción
B SI antecedente ENTONCES consecuente (IF-THEN)
C FUNCIÓN (parámetros) → resultado
D OBJETO.atributo = valor
✅ Correcto. Las reglas IF-THEN son la forma estándar de representación basada en reglas.
Pregunta 2 de 5
En la regla «SI temperatura > 38°C Y tos persistente ENTONCES sospechar neumonía», ¿cuál es el antecedente?
A sospechar neumonía
B neumonía
C persistente
D (temperatura > 38°C) Y (tos persistente)
✅ Correcto. El antecedente es la parte SI (LHS) — las condiciones que deben cumplirse.
Pregunta 3 de 5
¿Qué ventaja principal tienen las reglas en términos de explicabilidad?
A Se puede rastrear exactamente qué reglas se activaron y en qué orden para llegar a una conclusión.
B Las reglas nunca pueden estar equivocadas.
C No requieren mantenimiento ni actualización.
D Funcionan igual de bien con datos ruidosos que con datos limpios.
✅ Correcto. La trazabilidad es una fortaleza clave de los sistemas basados en reglas, especialmente en medicina y derecho.
Pregunta 4 de 5
¿Qué es el «encadenamiento» en sistemas de reglas?
A Un tipo de cerraduras de seguridad en sistemas informáticos.
B Ejecutar reglas en orden alfabético.
C Las conclusiones de una regla se convierten en hechos/premisas que activan otras reglas.
D Conectar físicamente múltiples computadoras en red.
✅ Correcto. El encadenamiento permite construir razonamientos complejos a partir de reglas simples.
Pregunta 5 de 5
¿Cuál es una limitación importante de los sistemas basados en reglas?
A No pueden procesar texto.
B Bases muy grandes (miles de reglas) se vuelven difíciles de mantener y pueden tener conflictos.
C Requieren más memoria que redes neuronales.
D Solo funcionan en supercomputadoras.
✅ Correcto. La escalabilidad es un desafío real en sistemas expertos complejos.

🎯 Conclusión

Las reglas son el mecanismo más intuitivo para capturar el conocimiento experto en sistemas de IA. Su naturalidad, modularidad y transparencia las hacen ideales para dominios donde la explicabilidad es crucial: medicina, derecho, soporte técnico, control industrial. Aunque tienen limitaciones con conocimiento muy complejo o difuso, siguen siendo la base de los sistemas expertos y la columna vertebral de motores de reglas empresariales como Drools, CLIPS y Jess. En la siguiente sección, exploraremos los métodos de inferencia que permiten a estas reglas razonar de manera efectiva.
